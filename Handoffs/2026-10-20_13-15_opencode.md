### 2.4 The D1 research, in brief

- **Netflix's own intro is authored code, not a media file.** The widely-shared recreations are
  pure HTML/CSS/JS or canvas. CNBC reported Netflix spent **two years** on the clip.
- **The industry answer to a web intro *with sound* is a separate audio track.** Video autoplay
  with sound is blocked by browser policy, so a `<video>` would have to be muted (score lost) or
  gesture-gated (breaking prompt-free autoplay). Web Audio has the same restriction — which is
  exactly why the original's discipline matters: **the visual animation never waits on the audio.**
- **To keep the main thread free, the pattern is a worker with an offscreen canvas** (Chromium's
  lottie player does this). Probably unnecessary for a 3-second sting, but it is the technique to
  reach for if profiling says otherwise.
- **Lottie/dotLottie is the industry vector tool**, and its `preserveAspectRatio` is the standard
  answer to responsive motion. **Not recommended here**, for three reasons: the existing design is
  already vmin-scaled; the original is deterministic code (`renderAt(t)` is one pure function of
  time, which is what makes it unit-testable and frame-verifiable); and it would add an
  After-Effects authoring dependency to a project that has none.

## 3. The facts a new session needs

### 3.1 Does the sequence depend on what lies underneath?

**Mechanically, no.** It never reads, samples, inspects or blends with the app — no DOM queries, no
colour extraction, no snapshot, no `mix-blend-mode`, no `BackdropFilter`.

**Compositionally, yes, and deliberately.** The curtain is **opaque obsidian** — `#05060a` (web) /
`Color(0xFF05060A)` (Flutter) — with translucent brand blooms over it. The app is fully covered
for most of the 3 s and is revealed by the two halves **sliding apart**.

**So the port must use a transparent stage carrying an opaque curtain over the mounted app.** An
opaque panel that is simply removed makes the outro a flash, not a reveal.

**The handover:** at `t >= curtain + 0.62` the overlay flips `pointer-events: none`, so the app
underneath is already interactive during the last ~0.38 s. Reproduce it.

### 3.2 The design is already resolution-independent

The web original scales by `--u: 1vmin` with `clamp()`; Flutter computes
`u = min(width, height) / 100`. The timing constants match exactly (`duration 3.0`,
`curtain 1.95`, `curtainEnd 2.75`). **D7 is largely a property to preserve, not to invent.**

### 3.3 The reference implementation and the oracle

- **Source:** `docs/opening-sequence/source/intro-overlay.html` (44.5 KB) — the original, preserved.
- **Oracle:** `docs/opening-sequence/scripts/capture_overlay_frames.py` drives `renderAt()` to
  capture reference frames; `serve_with_intro.py` injects the overlay over the running app
  independently of the app's own code. Together they give a **frame-for-frame** check.
- **Assets:** `docs/opening-sequence/assets/` — `intro-demo.mp4` (2.2 MB), `intro-demo-portrait.mp4`
  (2.4 MB, **stale** after D6), `intro-theme.wav` (529 KB, never played), 180 captured PNG frames
  (~280 MB), the stills.
- **Note:** `cdp_local.py` needs `websockets` (kept in the venv). The other scripts are stdlib.

### 3.4 The Flutter implementation

`flutter_client/lib/features/intro/presentation/widgets/brand_intro_overlay.dart` (26 KB) and
`presentation/controllers/intro_controller.dart` (1.1 KB). Tests:
`flutter_client/test/features/intro/brand_intro_overlay_test.dart` (3 widget tests) and
`intro_controller_test.dart` (4 unit tests).

Gating today: `IntroController.build()` sets `isPlaying: true` unconditionally, so the intro plays
on **every launch**; the `hasSeenIntro` field is set but never persisted or consulted. That is the
D2 "Android every launch" behaviour — **intentional**, but it should be *documented* rather than
accidental.
