## 3. The six findings, and what each cost

| # | Finding | How it was found |
|---|---|---|
| **F7** | The source's `mulberry32` re-seeds and re-mixes on **every call** — the whole body is inside the returned closure. The obvious "tidier" port, which hoists the initialisation out, produces a completely different sequence, and every particle lands somewhere else. | The canvas hash disagreed; a canvas-API trace showed the particles in a different order. |
| **F8** | `renderAt` measures the DOM **before** it writes to it, so every frame is drawn against the **previous** frame's geometry. The canvas is drawn *first* and the DOM written *after*. | The sheen disagreed at t=0.9: it reads the lockup's rectangle as it stood before the current frame's transform. |
| **F9** | The app's font stack leads with **Inter**; the source's does not. The overlay must set the source's own stack. | Predicted from reading `index.css:19`; would have broken the frame comparison. |
| **F10** | The source's brand SVG is **richer** than the app's — three paths, a specular highlight, a drop shadow. | The same read. |
| **F11** | The original paints frame zero **at load**. A port that does not accumulates a different history, and the compositor then rasterises the wordmark's glyphs differently — invisible to the eye, but 58 of 255 on a glyph edge. | The last difference standing; the port's harness now paints frame zero at mount. |
| **F12** | The `will-change` compositor hint changes a promoted layer's antialiasing, and the two documents promote the mark differently. | Isolated by removing the hint from both sides. |

**F7 was a real bug in the port**, caught by the oracle — exactly the class of error a
"frame-for-frame" claim is supposed to catch, and exactly the kind that a screenshot review would
have missed.

## 4. The oracle's three normalisations

Each is a *rendering mechanic*, not a design element, and each is documented in the spec (§13) and
in `web/e2e/intro-oracle.ts`:

1. **The camera shake's randomness.** The original draws it from `Math.random()`; the port's is
   deterministic (D9). The oracle patches the original's `Math.random` to hand it **exactly the two
   draws the port used**, so the original computes the same offsets from the same formula. The
   shake window is compared like any other — it is **not** skipped.
2. **The compositor hint** (`will-change`) is taken out of the comparison on both sides.
3. **The first frame.** The original paints frame zero at load; the harness does the same.

## 7. The rules that carried forward

Plan before executing (AGENTS.md §0.1); one slice at a time; do not weaken auth to make a test
pass; verify a deploy by **artefact timestamp**, not a health check; `.ps1` files must stay **pure
ASCII**; the Rust integration suite must never touch the production database.

**New for Phase 11:** the canonical spec states that **the source wins** on any disagreement, and
every value in it carries a `source: file:line` citation. When a later slice finds a discrepancy,
**fix the spec, not the code** — and record the fix.

**And the lesson of this slice:** *build the oracle before the thing it checks.* The
frame-for-frame harness was written first, and it found a real bug in the port (F7) that no
amount of reading would have caught.
