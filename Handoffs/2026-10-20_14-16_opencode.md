### 2.1 ⚠️ The Flutter suite was ALREADY RED before this change

**Three pre-existing failures**, unchanged by this slice, all in `setUpAll`:

```text
test/features/player/runtime_player_3a_test.dart: (setUpAll)
test/features/player/runtime_player_3b_test.dart: (setUpAll)
test/features/shell/app_shell_test.dart: (setUpAll)
```

**Cause:** `Exception: Cannot find libmpv-2.dll in your system %PATH%.` — those three files call
`MediaKit.ensureInitialized()`, and media_kit's **Windows** native libraries are not installed on
this host. The `media_kit_libs_windows_video-1.0.11` package is in the pub cache but ships no DLL.

**This is environmental, not a code defect.** The Flutter client targets **Android**, where media_kit
uses the Android backend and not libmpv — so the shipped app is unaffected; only these
host-side Dart-VM tests cannot run.

**Why it matters:** three test files — including `app_shell_test.dart` — cannot be executed on this
machine at all, so any change touching them is **unverified here**. That is a standing gap, not
something this slice introduced. AGENTS.md already carries the related rule: *"the rule not to
re-add `MediaKit.ensureInitialized()` to tests that do not need native playback."*

**Suggested follow-up (not done here — out of scope, and it means fetching a binary onto the
host):** either install the media_kit Windows libs so the suite is fully runnable, or drop the
`MediaKit.ensureInitialized()` call from the two `runtime_player_*` tests that do not genuinely need
native playback, and re-baseline.
