## 2. What was built

| File | What it is |
|---|---|
| `web/src/lib/intro/mode.ts` | **Pure.** Parses `?intro=` → `auto` \| `gate` \| `capture` \| `off`; anything unrecognised falls back to `auto`. |
| `web/src/hooks/useIntroSequence.ts` | The **container-owned** hook: the mode, the session gate, the capture handle. |
| `web/src/components/brand/BrandIntroOverlay.tsx` | Gains the `mode` prop, the gate card, the dismissal listeners, the capture behaviour, and the `window.__INTRO__` handle. |
| `web/src/components/brand/brand-intro.css` | The gate card's styles, ported from the source. |
| `web/src/app/AppShell.tsx` | Mounts the overlay as a **sibling** of `<main>`, so it plays over the login screen (D5). |
| `web/src/lib/intro/mode.test.ts`, `web/src/components/brand/BrandIntroOverlay.test.tsx` | 17 new tests. |

**The four modes:** `auto` (the default; once per browser session) · `gate` (the manual-testing
card; never the product behaviour) · `capture` (a still page, driven from outside) · `off`
(nothing is mounted at all — the component is never in the tree).

**The gate's ownership.** The container reads `sessionStorage.introSeen` **during render**, decides
whether to mount, and records that the intro has started. **The overlay has no `sessionStorage`
reference at all** — asserted against the component's own *source*, not merely at runtime, because a
runtime spy would only prove it for the paths a test happens to exercise.

**The decision is made once, at mount**, in a `useState` initialiser rather than an effect. Under
`StrictMode` — which the app enables — effects run twice, so an effect-time read would see the flag
the container had just written itself, decide the intro had already been seen, and **never play it at
all**. There is a test for exactly that.

## 3. Five findings, all from reading the source rather than the plan

| # | Finding |
|---|---|
| **F13** | **The original's click-to-skip is dead.** It tests `e.target === el.stage` (source 888), but the FX canvas (z-index 4) and the curtain halves (z-index 2) have no `pointer-events: none` — so a click always lands on one of them and never on the stage. The canonical spec requires click/tap to dismiss, and the Flutter client dismisses on a tap anywhere, so **the port follows the spec**. |
| **F14** | The original's auto mode has an escape hatch: `intro=(auto\|replay\|force)` plays the intro **even when it has been seen** (source 976). That is a Replay mechanism, so **D4 removes it** — the session gate is unconditional, and `?intro=gate` is the manual way to watch it. |
| **F15** | The original's `gate` mode does **not** consult the session gate. The port matches that, and additionally records the intro as seen when a gate view starts. The `capture` mode deliberately does **not** record it: a verification run must not consume the user's session. |
| **F16** | **The curtain does not hide the page until it has fully parted.** The halves' inner edges are **feathered** — the source gives each a mask whose transparent band is `4 + 11 × progress` percent of the half's width. The band of the page the curtain does not fully hide is the gap **plus** those two feather bands, and it is the only place the app's own content can show through. |
| **F17** | A **conditional hook call**: `useIntroSequence` was placed after the `/remotelogin` early return, which `oxlint`'s rules-of-hooks caught. The hook is now called before the return, and the early return still skips the mount. |

**F16 is the one that cost the most to find.** The shipped-app comparison failed at t=2.1 with a
difference band of x 877–1042, which matched the feather band to the pixel — the difference is the
app's own library showing through the curtain's feathered inner edges, which is correct behaviour,
not a bug. The oracle now derives the band from the timeline rather than hard-coding it.

## 5. What is next

**Slice 11.3a — the web Web Audio score.** The score, and nothing else. D8: **live Web Audio
synthesis on the web** — the original's own approach, zero asset bytes — with the non-blocking
discipline AGENTS.md makes an invariant: the animation never waits on the audio, and the
`AudioContext` resumes on the first gesture.

- Port the original's audio module (source 572-807, **236 lines**).
- The gate card's wording changes with it: the button becomes "Play with sound" and the hint
  describes the keys, exactly as the original's does. (It currently says "Play" — honest, because
  there is no sound yet.)
- **The oracle is a measurement, not a listening test:** the port's synthesis is rendered in an
  `OfflineAudioContext` and the samples are compared against
  `docs/opening-sequence/assets/intro-theme.wav` — which is the offline render of that same
  composition. The score becomes *provably* the same music rather than probably.
- The animation must remain provably unblocked by a suspended `AudioContext`.

**It has not been planned.** Per AGENTS.md §0.1, plan it only when the owner asks.

## 6. The rules that carried forward

Plan before executing (AGENTS.md §0.1); one slice at a time; do not weaken auth to make a test
pass; verify a deploy by **artefact timestamp**, not a health check; `.ps1` files must stay **pure
ASCII**; the Rust integration suite must never touch the production database.

**New for Phase 11:** the canonical spec states that **the source wins** on any disagreement, and
every value in it carries a `source: file:line` citation. When a later slice finds a discrepancy,
**fix the spec, not the code** — and record the fix. Twice now, that rule paid for itself: F13
(the dead click-to-skip) and F14 (the replay escape hatch) were both *spec* corrections, not code
changes.

**And the lesson of this slice, again:** *build the oracle before the thing it checks.* The
shipped-app comparison found F16 on its own — the feathered inner edges — and without it the
shipped path would have been unverified.
