## 3. The oracle — and what it caught

**The reference is the original's own Web Audio, not the WAV.** This was the plan's biggest
correction. `intro-theme.wav` is the *Python* renderer's output (`render_intro_theme.py`, seeded at
line 50), and the Python sweeps a resonant **low-pass** over its noise beds where the original's
Web Audio uses a **band-pass**. The two are not the same synthesis — the source's own comment that
the Web Audio "mirrors `render_intro_theme.py` 1:1" is about the *composition*, not the samples.
The WAV is the **Flutter** client's reference (it plays the file, Slice 11.5); the archived
overlay's `window.INTRO.audio` is the **web** port's.

The oracle therefore renders the archived original in an `OfflineAudioContext`, with
`Math.random` replaced by the port's own seeded PRNG, so the original's noise draws and the port's
come from the same sequence in the same order.

| Level | Assertion | Result |
|---|---|---|
| The composition | `score-golden.json` against the port's voice table | **exact** |
| **The graph** | every node the original's score creates, counted by kind | **exact** — 33 oscillators, 11 noise buffers, 78 gains, 23 filters, 36 panners, 1 convolver, 1 compressor, 2 shapers |
| The signal | the port's render against `intro-theme.wav`, on the score's envelope (20 windows of 155 ms) | within **16 dB** in every window; the peak within **1.3 dB** |
| Reproducibility | two renders of the port's own score | identical to within **1 × 10⁻⁴** |

**Two real defects in the port, both invisible to a listening test:**

1. **The oscillators bypassed their envelopes.** The plain oscillators and the saturated sub were
   connected *directly to the bus* as well as into their envelope gain, so raw full-amplitude
   sines rode on top of the mix. The port rendered **3.5× too loud** and clipped.
2. **The riser had a spurious 120 Hz high-pass.** The original builds the riser **inline**
   (`source: 709-714`) rather than through `noiseVoice`, so it has no high-pass and its sweep ends
   at `t + 0.60` rather than at the generic `dur × 0.9`. Counting the nodes by kind found it in
   one run: the port built **24 filters** where the original builds **23**.

**A third defect the oracle found before it could even run:** the port's original noise voices all
shared one filter type, one Q and no high-pass. The source's noise beds are *not* interchangeable —
the riser is a band-passed sweep, the ticks are a low-passed click, the handoff chime's noise is a
band-passed wash, each with its own envelope. The score is now a table in which every parameter of
every voice is explicit.

## 4. The behaviour that is new (not in the original)

| | The original | The port |
|---|---|---|
| A suspended context | the whole score is scheduled against `ctx.currentTime + RAMP`, and a frozen clock holds it — the score plays in full, from the top, whenever the context finally resumes, possibly long after the animation ended | the score is **anchored** to the animation's clock (`ctx.currentTime + RAMP - elapsed`), a voice whose beat has passed is **skipped**, and a context that resumes after the animation has ended gets **no score at all** |
| The unlocking gesture | resumes the context, and the same gesture also dismisses the intro | the first gesture is **consumed by the audio** and the animation continues (D12) |
| `m` | mutes (and does not skip) | mutes (and does not dismiss) — ported, because the restored gate hint says it does |
| The noise | `Math.random()` | seeded (D13) |

## 7. The open finding

**The port's score renders about 6 dB quieter than the archived original's own Web Audio**, under
an offline render: the original measures a peak of 1.213 and an RMS of 0.376, the port a peak of
0.613 and an RMS of 0.067. The original's peak **exceeds full scale**.

Everything that could be measured **was** measured, and ruled out:

| Hypothesis | Measurement | Verdict |
|---|---|---|
| The score is built twice | the original creates exactly **33** oscillators — the score's oscillator count, once — and the port creates 33 | **ruled out** |
| The reverb | replacing the original's `ConvolverNode` with a zero gain changes its level by 0.1 % | **ruled out** |
| A different graph | every node kind matches exactly | **ruled out** |
| Different noise | both draw from the same seeded stream, in the same order | **ruled out** |
| The `seqBus` gain schedule | the port's was made faithful to the source's in this slice | **ruled out** |

**The port's level does match the shipped WAV** — within **1.3 dB in peak** (0.613 against 0.709) —
and its envelope tracks the WAV's within **16 dB** in every window. So the port is at the level of
the audio the Flutter client ships, and the archived original's live Web Audio is the outlier. But
*why* it is the outlier is **not known**, and it is recorded as an open finding rather than papered
over. Spec §7.9 carries the same list.

**It does not block 11.3a**: the oracle proves what 11.3a set out to prove — the same composition,
the same graph, the same score. But it is unresolved, and it is in `AGENTS.md`'s work queue.
