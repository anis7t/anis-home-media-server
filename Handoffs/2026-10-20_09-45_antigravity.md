## 2. Completed Architecture & Deliverables

### A. Database (PostgreSQL 18.4)
- **Table `device_pair_sessions`** added to `ensure_schema()` in [`rust/src/db.rs`](../rust/src/db.rs):
  - `id`: Text/UUID primary key (`qr_<token>`).
  - `code`: 5-character uppercase alphanumeric code (e.g. `K7R2P`).
  - `code_hash`: SHA-256 hash for secure matching.
  - `sig`: HMAC-SHA256 signature (`qr_id:code`) keyed with `MEDIA_SERVER_SECRET` for tamper-proof QR query parameters.
  - `user_id`: Bound upon phone confirmation.
  - `session_id`: Minted 30-day session token (`sess_<token>`) for the waiting TV.
  - `device_name`: Friendly name entered by the phone user (e.g., "Living Room TV").
  - `confirmed`: Boolean flag toggled upon phone authorization.
  - `expires_at`: 2-minute ephemeral TTL with an index (`idx_device_pair_expires`).

### B. Rust Backend Services & Endpoints (`MediaServerRust`)
1. **[`rust/src/services/auth_service.rs`](../rust/src/services/auth_service.rs):**
   - `generate_pair_code()`: Generates unambiguous 5-char alphanumeric codes (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, omitting `0`, `O`, `1`, `I`).
   - `hmac_pair_code()`: Computes HMAC-SHA256 signature for URL parameters.
   - `create_pair_session()`: Inserts unconfirmed pair record and returns `(qr_id, code, sig, expires_at)`.
   - `get_pair_session_status()`: Returns `(confirmed, session_id, device_name)`.
   - `find_pair_session_by_code()`: Looks up active sessions by 5-char code to support manual URL entry on phones.
   - `confirm_pair_session()`: Validates code/sig, mints a 30-day session token, records `device_name`, and confirms the session.
   - `sweep_expired_pair_sessions()`: Cleans up expired pairing sessions.
2. **[`rust/src/routes/qr_auth.rs`](../rust/src/routes/qr_auth.rs):**
   - `POST /api/auth/qr` $\rightarrow$ Generates QR session with dynamic `qr_url` and `login_url` based on request host headers.
   - `POST /api/auth/qr/lookup` $\rightarrow$ Validates manual 5-digit code entry from phone and returns `qr_id`.
   - `GET /api/auth/qr/{id}/wait` $\rightarrow$ Server-Sent Events (SSE) push stream (`data: pending`, `data: confirmed`, `data: expired`).
   - `GET /api/auth/qr/{id}/status` $\rightarrow$ JSON polling fallback endpoint (`pending` | `confirmed` | `expired`).
   - `POST /api/auth/qr/{id}/confirm` $\rightarrow$ Authenticated phone confirmation endpoint receiving `device_name` and `code`/`sig`.
   - `GET /api/auth/qr/{id}/finalize` $\rightarrow$ TV finalization endpoint that issues `Set-Cookie: session_token=sess_...`, persists the friendly device name to `devices.custom_name`, and redirects to `/`.
3. **[`rust/src/lib.rs`](../rust/src/lib.rs):**
   - Mounted `qr_auth_routes` under the primary Axum router.
